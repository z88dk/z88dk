# Instructions the T-state model scores differently from the emulator, per CPU. check.c fails
# when a count changes, either way: lower an entry when the model improves.
#
# z80, z80n and z180 match the emulator on every instruction in instructions.txt, so they have no entry.
#
# 8080, 8085, vm1, gbz80: z80asm expands adc/sbc hl,rr, ld rr,(nn), neg, rld, ldi and cpd into
# inline sequences that the model does not score (the compiler does not emit them), and a few
# branch forms differ from the emulator.
8080 19
8085 15
vm1 15
gbz80 23
# ez80_z80: the emulator does not implement tstio, so it runs the next byte as an instruction (9).
ez80_z80 1
#
# kc160: the model and the emulator follow the KC160 instruction table (Appendix A, odd/even clock
# pair, first column). ldi, cpd, ini and outd are not in the model's table: their clock counts are not
# in the text of the manual that could be read.
kc160 4
# r2ka, r4k, r6k: the model follows the Rabbit instruction manual (R2000/R3000/R4000) and the Rabbit
# 6000 instruction spreadsheet (R6000, 8-bit fetch). The R4000 and R6000 runs set EDMR first, as the
# startup code does. The Rabbit has no daa, rld or rrd: z80asm emits a helper sequence, scored at its
# cost. It has no conditional call either: z80asm emits jr !cc over a call, scored as that. The one
# difference left is the taken call in instructions.txt: its target $+3 is the end of the call on a
# Z80 but the middle of the five-byte Rabbit expansion, so the emulator runs two stray instructions.
r2ka 1
r4k 1
r6k 1
# r800: the model has no timings for this CPU, so it scores it with Z80 numbers.
# Replace the entry with 0 as the timings are added.
r800 190
