fnptr dispatch goes through it. Only the fastcall, __sdcccall(1) and far
dispatches do; a plain near call is `call l_jphl` and never touches IX, so the
push/pop (4 B, 30 T) was dead. Narrowed to the calls that dispatch via IX.

3/10/2026 — jump to the label below (jp-next): the shared return block is

3/10/2026 — call arguments with control flow (ir_build, arg-reorder): a ?:,
&& or || argument ends the basic block, and pushes at the producer need the
whole call in one block, so every argument built before it went through a
frame slot (the framework's failure printf spilled six values, three of them
plain global loads). When every argument is side-effect-free and at most one
touches a volatile, evaluation order is unobservable: the control-flow
arguments are now built first and the rest push in place. test.c: -36 B fp /
-46 B sp on z80. 80cc-fp and 80cc-sp: 682 cells changed, 0 grown, -20460B
total, none slower; other columns untouched. Corpus sources and

3/10/2026 — dead indirect-call target spill (op_dst_spill_is_dead): a
zero-argument near indirect call reads its function pointer straight from HL,
but the allocator only knew that for an op's src[0] or an LD_MEM base, so the
target's def still stored a frame copy nothing read. The shared framework
test.c does this four times in suite_run (setjmp keeps every value in memory).
The case is now recognised; argument, far, fastcall, sdcccall, long-long and
critical calls keep the slot. test.c: -7..-23 B on every CPU (-20 B fp /
-21 B sp on z80). 80cc-fp and 80cc-sp: 682 cells changed, 0 grown, -10695B
total, none slower; other columns untouched.

3/10/2026 — string-literal remat (IR_LD_STR rematerialised, no longer
hoisted by LICM): a string-literal address is a link-time constant like &sym,
but only LD_IMM/LD_SYM/LEA were in the remat table, so every literal that met
register pressure took a frame slot and a store, and LICM hoisted loop
literals into a loop-long slot. The shared framework test.c (suite_run, seven
literals plus a five-argument printf) paid it in every binary. LD_STR is now
recomputed at each use and left in the loop. test.c: -96 B sp / -84 B fp on
z80, -28..-116 B on every CPU. 80cc-fp and 80cc-sp: 682 cells changed, 0
grown, -46091B total, 15 cells faster, 2 slower by 0.01M (md5 fp r4k/r6k);
other columns untouched.

2/10/2026 — mulchain-de (Horner shift-add chain, DE-resident operand):
a const-multiply strength-reduction chain whose multiplicand had no register
home reloaded it from the frame on every term (plus an `ex de,hl` swap each
time), because the generic binop loader has no memory that it read the same
vreg one step ago. Post-render peephole: load the multiplicand into DE once,
before the first doubling, and delete every ex/reload pair after — DE is
provably dead there by construction of the existing swap-and-reload shape, so
no liveness check is needed. fp-only (the shape is `ld hl,(ix+d)`-keyed); sp
mode is untouched. 80cc-fp: 35 cells changed, 0 grown, -876B total (other
columns untouched).
